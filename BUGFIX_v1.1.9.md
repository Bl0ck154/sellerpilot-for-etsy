# 🐛 Bugfix v1.1.9 - API Key Storage Issue

## Проблема

Користувачі скаржилися що:
1. При спробі відправити повідомлення розширення запитувало API ключ
2. Після введення ключа та збереження знову відкривалось вікно налаштувань
3. Ключ наче зберігався, але розширення його не бачило
4. Проблема виникала після оновлення розширення через `chrome.runtime.reload()`

## Причина

**Extension Context Invalidation** після перезавантаження розширення:

1. При оновленні розширення викликається `chrome.runtime.reload()` (service_worker.js:59)
2. Extension context стає invalid на короткий час
3. `safeStorageSet()` повертає `false` замість збереження ключа
4. **Критичний баг**: Код не перевіряв результат і показував "✅ API Keys Saved" навіть коли збереження не відбулося
5. При наступній спробі відправити повідомлення - ключа немає
6. Автоматично відкривається Settings з пустими полями
7. Якщо користувач натисне Save з пустими полями → перезапише існуючий ключ пустим значенням

## Виправлення

### 1. `saveSettings()` (chat_ui.js:663-680)
- Додана перевірка результату `safeStorageSet()`
- Якщо збереження провалилось → показується помилка та Settings НЕ закриваються
- Користувач бачить чіткі інструкції: "❌ Failed to save API keys. Please reload this page (F5) and try again."

### 2. `loadConfiguration()` (chat_ui.js:444-450)
- Додана перевірка `if (!result)` з чітким повідомленням
- Settings НЕ відкриваються автоматично якщо storage недоступний
- Показується: "⚠️ Extension is initializing. If this persists, please reload the page (F5)."

### 3. `openSettings()` (chat_ui.js:606-622)
- Змінена на `async function` для правильної перевірки результату
- Settings НЕ відкриваються з пустими полями якщо storage недоступний
- Показується: "❌ Cannot open settings - extension is reloading. Please reload this page (F5) and try again."

### 4. `openSettingsForProvider()` (chat_ui.js:625-660)
- Те саме виправлення що і для `openSettings()`
- Запобігає відкриттю Settings з пустими полями після перезавантаження

## Результат

✅ API ключ більше не губиться після оновлення розширення  
✅ Користувач отримує чіткі повідомлення про помилки  
✅ Settings не відкриваються з пустими полями  
✅ Захист від випадкового перезапису збережених ключів  
✅ Чіткі інструкції що робити (Reload page F5)  

## Тестування

1. Ввести API ключ і зберегти
2. Оновити розширення (змінити версію в manifest.json)
3. Спробувати відправити повідомлення
4. Переконатись що API ключ збережений і працює
